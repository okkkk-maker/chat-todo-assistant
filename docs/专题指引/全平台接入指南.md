# 全平台接入指南

> 目标：让「全平台协同模式」真的跑完，而不是界面上打了勾、实际 0 条。
> 本文只讲**要开通什么、要配什么、怎么验证**；实现细节见 `tools/channels/`。
>
> **⚠️ 重要测试状态与启用前必读**：
> - **尚未经过实机测试的通道**：**飞书（Feishu）** 与 **钉钉（DingTalk）** 通道目前**尚未经过完整实机测试**（属于实验性接入支持，实机验证目前仅覆盖 QQ、个人微信与企业微信推送）。
> - **使用前置步骤**：首次启动程序后处于待命状态，无论启用哪个平台，都**必须先前往控制台【⚙️ 系统设置】确认配置模式、勾选对应平台并完成测试/保存后才能正式使用**（首次启动向导不会自动启用飞书和钉钉）。

## 一、先看清分工（这是能跑通的前提）

```
                    ┌──────────────────────────────┐
   本机本地数据 ────► │  QQ      本地解密             │──┐
                    │  微信    本地明文镜像          │  │
                    └──────────────────────────────┘  │
                                                       ├──► channel_collector
                    ┌──────────────────────────────┐  │    （去重/排序/判定/落盘）
   云端 API ────────► │  飞书    Open API 主动拉      │──┤           │
                    └──────────────────────────────┘  │           ▼
                                                       │   work/待办素材.json
                    ┌──────────────────────────────┐  │           │
   WorkBuddy 连接器 ► │  企微    连接器写入收件箱     │──┘           ▼
   钉钉回调/存档   ► │  钉钉    同上                 │      WorkBuddy 提炼 + 推送
                    └──────────────────────────────┘
```

关键点：**企业微信和钉钉的消息读取能力不在本 Python 进程内**。
企微靠 WorkBuddy 的 `wecom` 连接器，钉钉靠企业后台的「会话内容存档」。
所以这两个通道设计成「收件箱模式」——谁取到都行，取到写进 `work/inbox/` 就行。

## 二、可行性矩阵（先看这张表再动手）

| 通道 | 能否由程序自己拉 | 实机测试状态 | 依赖 | 卡点 |
|---|---|---|---|---|
| QQ | ✅ 能 | ✅ 已实机验证 | `QQ_DBKEY` + `config/schema.json` | 需 `Admin_Init` 跑一次（Frida 挂 QQ） |
| 个人微信 | ✅ 能 | ✅ 已实机验证 | `WX_DBKEY` + `vendor/wechat-key` | 需本机登录过微信 4.x；首次要解密全库 |
| 飞书 | ⚠️ 理论可行 | ⚠️ **尚未经过测试** | 自建应用 `App ID/Secret` | **须先在系统设置确认配置，且应用必须被拉进群** |
| 企业微信 | ❌ 不能（走连接器） | ✅ 推送已验证 | WorkBuddy `wecom` 连接器 | 需连接器授权；853006 = 未开会话存档 |
| 钉钉 | ❌ 不能（走存档/回调） | ⚠️ **尚未经过测试** | 会话内容存档 或 机器人回调 | **须先在系统设置确认配置；需企业单独开通存档** |

**结论**：日常建议优先使用已验证的 **QQ + 个人微信 + 企微推送**；**飞书和钉钉尚未经过实机测试**，如需使用请先前往控制台 **【⚙️ 系统设置】** 勾选平台、测试连通性并保存配置后再运行。

### 2. 个人微信（Windows 4.x）

**前置**：本机装了微信 4.x 且已登录（存在 `xwechat_files/<wxid>/db_storage`）。
**不需要**再拷贝 `vendor/`：解密内核已内置在 `tools/wxdecrypt.py`。

**步骤**

1. 打开微信并保持登录（**必须是你自己在桌面上双击启动的**；由脚本/后台拉起的
   微信常常是"空壳"，不会打开数据库，也就不会有密钥可抓）。

2. **取密钥（4.0.x 与 4.1+ 同一套操作）**

   确认微信已登录（窗口标题是你的昵称）→ 点「🔑 自动抓取微信密钥」，
   等价命令：`python tools\wxkey.py acquire`。通常 **2~3 秒**完成，不需要关微信。

   程序内部按版本走两条路：
   - **4.0.x**：扫内存里的 `x'<key><salt>'` 缓存；
   - **4.1+**：定位 `com.Tencent.WCDB.Config.Cipher` 对象 → 沿对象链取 blob →
     XOR 固定掩码解码 → 得到 `x'<64hex key><32hex salt>'`。

   两条路取到的密钥都必须通过 **page 1 HMAC-SHA512 校验**才写入 `.env`。
   4.1+ 是**每库一密钥**，一次抓取会把 `message_N.db` / `contact.db` / `session.db`
   等全部库的密钥一起取到，存进 `work\wx_keys.json`（这叫密钥环）。

   「🚀 启动时抓取」是兜底方案（frida 挂载 + 捕获 PBKDF2），只有在上面的路子
   取不到时才需要；它要求你手动重启微信，正常情况下用不到。

3. 抓不到时的排查顺序：
   - 确认 `Weixin.exe` 在跑、窗口标题是你的昵称（没登录就没有密钥）；
   - 控制台是否以管理员身份运行（读进程内存需要权限）；
   - 微信是否**桌面手动启动**的（脚本/后台拉起的是空壳，不读数据库）；
   - 用 `python tools\wxkey.py status` 看密钥环覆盖了几个库；
   - 仍不行就粘贴 64 位密钥，或用「🚀 启动时抓取」。
   详细原因与现象对照见 `docs/微信密钥抓取-超时与卡死排查.md`。

4. 首次采集会自动生成明文镜像到 `work\wx_mirror\<wxid>\db_storage`，
   之后每轮只增量刷新（源库比镜像新才重解）。可手工触发：
   ```bash
   .venv\Scripts\python.exe tools\wxkey.py status
   ```

5. 控制台勾选「个人微信」并保存，点「立即采集」。

**验证**：`work/待办素材.json` 里出现 `"source": "WeChat"` 的条目；
控制台「微信」灯显示「本地解密就绪（读明文镜像）」。

**注意**
- 只读：只读原始库文件与 `-wal`，不开写事务；镜像写在程序自己的 `work/` 下；
- 合规：仅限本机、本人有权访问的数据；密钥等同于全部聊天解密能力，不要外发；
- 换微信号 / 微信重装 / 大版本升级后，旧密钥必然失效 —— 程序会报
  `密钥与当前数据库不匹配`，重新抓一次即可；
- 表结构随版本变化，报 `N 张表结构不符（微信版本差异）` 时其余会话仍会正常读，
  只是那几张表被跳过（会在备注里写明张数，不会静默）。

### 3. 飞书（尚未经过实机测试 · 实验性）

> **⚠️ 提醒**：飞书通道目前**尚未经过实机完整测试**。配置完凭证后，必须进入控制台 **【⚙️ 系统设置】** 勾选「飞书」、点击测试连通性并保存确认后才能生效。

**步骤**

1. [飞书开放平台](https://open.feishu.cn/app) → 创建**企业自建应用**
2. 「权限管理」开通：
   - `im:message:readonly` —— 读取单聊/群聊消息（必需）
   - `im:chat:readonly` —— 读取会话列表（必需）
   - 可选 `contact:user.base:readonly` —— 拿发送人真名
3. 「凭证与基础信息」拿 `App ID` / `App Secret`
4. **把应用拉进要读取的群**（群设置 → 群机器人/应用 → 添加）。
   ⚠️ 这一步最容易漏：没入群的群，API 里根本不会出现，程序只能报"可见会话数为 0"
5. 发布版本并等待管理员审核通过
6. 写进 `.env`：
   ```
   FEISHU_APP_ID=cli_xxxxxxxx
   FEISHU_APP_SECRET=xxxxxxxx
   FEISHU_MAX_CHATS=60
   # 可选：把 open_id 映射成人名（没有通讯录权限时很有用）
   FEISHU_SENDER_MAP={"ou_xxxx":"王主任","ou_yyyy":"李老师"}
   ```

**验证**
```bash
%PY% -c "import sys;sys.path.insert(0,'tools');from channels import feishu;import common,time;r=feishu.fetch(common.load_env(),time.time()-3600,time.time());print(r.status,r.message,r.note)"
```

**调参**
- 群很多 → 调大 `FEISHU_MAX_CHATS`（默认 60，每轮遍历所有会话，越多越慢）
- 报 `code=99991663` → token 无效，检查 App ID/Secret
- 报 `code=99991400` → 触发频控，把 `FEISHU_MAX_CHATS` 调小或拉长采集间隔

### 4. 企业微信（连接器模式）

**路径 A：WorkBuddy 连接器（推荐）**

1. WorkBuddy → 连接器管理 → 企业微信 → 授权并信任
2. 定时任务里由提示词第 1 步调用连接器，把消息写进收件箱

**路径 B：群机器人 Webhook（只能发，不能收）**
只用于推送兜底，`WECOM_WEBHOOK_URL`，**不解决读取**。

**已知限制**：企微群聊历史消息需企业开通「会话内容存档」，
未开通时连接器会返回 `853006`，此时企微通道为空——这是平台限制，不是程序 bug。

**验证**
```bash
%PY% tools\inbox_push.py --channel WeCom --dry-run --file work\inbox\_staging_wecom.json
%PY% tools\inbox_push.py --channel WeCom --file work\inbox\_staging_wecom.json
# 然后跑采集，channel_stats.WeCom.status 应为 OK
```

### 5. 钉钉（尚未经过实机测试 · 需确认存档权限）

> **⚠️ 提醒**：钉钉通道目前**尚未经过实机完整测试**。启用前请先确认具备企业会话存档或机器人回调能力，并必须在 **【⚙️ 系统设置】** 勾选「钉钉」且点击「保存配置并应用」确认后才能使用。

钉钉**没有**"读我所有群消息"的开放接口。两条可行路径：

| 路径 | 前提 | 落地方式 |
|---|---|---|
| 会话内容存档 | 企业开通（付费/需审批），有 `dd-archives` 拉取能力 | 写脚本拉到消息 → `inbox_push.py --channel DingTalk` |
| 机器人回调 | 需公网可达的回调地址；只能收到 @机器人 的消息 | 回调里转存 → 同上 |

如果两条都不具备：**建议在控制台取消勾选钉钉**。
不勾选 = `DISABLED`（不参与判定，不会告警）；
勾了但没接入 = `NOT_INSTALLED`（每次都会提示"尚未接入"，会打扰人）。

**验证**：同企微，把 `--channel` 换成 `DingTalk`。

## 五、状态码对照表

| status | 含义 | 要不要处理 |
|---|---|---|
| `OK` | 采集成功 | 否 |
| `STALE` | 成功但数据源陈旧（如微信库没更新） | 看一眼 |
| `FAIL` | 尝试了但失败（网络/凭证/解密） | **要修** |
| `NOT_CONFIGURED` | 勾了但没填凭证 | **要修** |
| `NOT_INSTALLED` | 平台侧还没接上（缺 vendor / 收件箱空） | 按需配 |
| `NOT_IMPLEMENTED` | 平台无可用接口/权限不足 | 只能换路径 |
| `DISABLED` | 没勾选 | 否 |

整体 `meta.status`：

| 值 | 含义 | 提示词首行 |
|---|---|---|
| `OK` | 全部通道正常 | 🟢 |
| `STALE` | 有通道数据陈旧 | 🟢/🟡 |
| `PARTIAL` | 有数据，但部分通道没采到 | 🟡 |
| `FAIL` | 勾选的通道全部失败 | 🔴 |
| `NOT_READY` | 勾选的通道都还没接入 | 🔴 |
